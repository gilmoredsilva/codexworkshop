Demonstration

A small map of the GitHub workflow: copy a project, record your work, share it, and bring changes back together.

The command line

01 / 03

01

Clone the repository

git clone https://github.com/
  username/repository.git

Downloads the repository and its history to your computer. Run this once when you first join a project.

02

Stage your changes

git add .

Places all changed files into the next snapshot. Check what is staged with git status.

03

Save a snapshot

git commit -m "Describe
  the change"

Records the staged snapshot in your local history with a message your team can understand.

04

Send it to GitHub

git push origin main

Uploads your local commits to the remote repository. The remote branch now has your work.

05

Bring work down

git pull origin main

Fetches remote commits and integrates them into your current branch. Pull before you start work.

06

Check your state

git status

Shows your current branch and which files are modified, staged, or ready to commit.

Branches are parallel timelines

02 / 03

A branch is a movable pointer to a line of commits.

main stays ready and stable. A feature branch gives you a safe place to work. When the feature is complete, the histories can be merged.
